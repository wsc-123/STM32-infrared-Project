# 米家接入说明

记录日期：2026-08-03。

## 接入结果

本项目通过巴法云的第三方平台能力接入米家，不更换 STM32F103C8T6 或 ESP-01S。固件使用同一条 TCP 连接同时订阅两个主题：

```text
Android App -> infrared ─────┐
                             ├-> ESP-01S -> STM32 -> 红外 -> 空调
米家/小爱   -> infrared005 ──┘
```

- `infrared`：原 Android App 的控制、学习和诊断主题。
- `infrared005`：主题名以 `005` 结尾，巴法云将其识别为空调并同步给米家。
- `infrared/up`：固件回传 `OK/ERR` 等详细执行结果。
- `infrared005/up`：固件只更新标准空调状态，不向 STM32 回推，避免自触发。

## 巴法云配置

在 TCP 设备云中保留或创建以下两个主题：

| 主题 | 昵称 | 用途 |
|------|------|------|
| `infrared` | 任意 | 原 App、学习、诊断 |
| `infrared005` | 空调或更具体的名字 | 米家和小爱控制 |

两个主题使用同一巴法云账号和私钥。固件上线后，两张主题卡片都应显示“订阅者：在线 1”。

## 米家绑定

1. 打开米家 App。
2. 进入 `我的 -> 其他平台设备 -> 添加`。
3. 选择“巴法”，登录当前巴法云账号。
4. 看到空调设备后点击“同步设备”。

巴法设备属于第三方平台设备，米家会提示“不支持设置家庭和房间”。它通常不会作为原生设备卡片显示在米家首页，也不能获得完整的米家自动化能力；主要使用方式是小爱语音控制。设备可在 `我的 -> 其他平台设备 -> 巴法` 中查看。

## 命令映射

| 米家/巴法消息 | STM32学习槽 | 实际动作 | 状态回传 |
|---------------|-------------|----------|----------|
| `on` | 0 | 开机 | `on` |
| `off` | 1 | 关机 | `off` |
| `on#2` / `on#2#26` | 2 | 制冷26度 | `on#2#26` |
| `on#2#23` | 3 | 制冷23度 | `on#2#23` |
| `on#7` | 5 | ECO模式 | `on#7` |

槽4是屏显切换，不属于标准空调状态，继续通过原 Android App 控制。其他温度、制热、独立风速和扫风没有对应学习码，固件会返回 `ERR MI unsupported`，不会发送一个可能错误的近似红外码。

## 实测记录

2026-08-03 完成以下验证：

1. `infrared` 和 `infrared005` 均显示订阅者在线。
2. 向 `infrared005` 下发 `on#2#26`。
3. `infrared` 收到 `OK sent MI cool26 (299 edges)`。
4. STM32完成红外发送，空调动作正常。
5. 米家成功识别巴法云中的空调设备并完成同步。

这证明链路 `米家/巴法云 -> ESP-01S -> STM32 -> 红外 -> 空调` 已经打通。

## 状态限制

红外发送是单向链路，STM32不能读取空调内部的真实状态。米家看到的是最后一次由本项目成功发送的状态；如果有人使用原装遥控器操作空调，米家显示可能与空调实际状态不同。

## 故障判断

| 现象 | 检查方向 |
|------|----------|
| 两个主题都离线 | ESP供电、AT通信、Wi-Fi和巴法云连接 |
| `infrared`在线但`infrared005`离线 | 是否烧录双主题固件、主题名是否完全一致 |
| `infrared005`收到命令但没有执行回复 | 下行topic解析或STM32固件版本 |
| 返回`empty(slot n)` | 对应红外槽没有学习数据 |
| 返回`OK sent`但空调无动作 | 红外LED、三极管、发射功率、对准方向和学习质量 |
| 米家首页没有设备卡片 | 第三方平台设备限制，属于正常现象 |
